## ⚠️ THE PHASE 2 CONSTRAINT — read before planning anything

**"Register the 12 fr-source tracks" CANNOT be done inertly, and the naive reading of it
violates the autonomy rules.** Phase 1 proved why:

`listNativeLanguages()` (`data/tracks/index.js`) derives the onboarding and Settings
native-language picker from `new Set(listTracks().map(t => t.nativeLang))`. So the moment
`enUsForFr` / `enGbForFr` are added to `TRACKS`, **Français appears in the picker** and a user
can select it. That is the offering flip, and it needs my sign-off.

**So Phase 2 is scoped like this instead:**

1. **Author** `data/tracks/enUsForFr.js` and `data/tracks/enGbForFr.js` (English targets for
   French natives — model on `enUsForPt.js` / `enGbForPt.js`). Write the files. **Do NOT import
   or register them in `data/tracks/index.js`.**
2. **Build the 10 side tables** `data/tracks/l10n/<track>.fr.js` for:
   `es-latam-for-en`, `es-spain-for-en`, `pt-br-for-en`, `pt-pt-for-en`, `it-for-en`,
   `de-for-en`, `ru-for-en`, `ja-for-en`, `ko-for-en`, `zh-for-en`.
   Prefer **translating the existing `.es.js` or `.pt.js` in place** — that carries the Word Bank
   (fvocab) for free. Building from a base track instead means replaying `buildFrequencyBank` and
   asserting per-item option-length parity (0 mismatches). Note which source each was translated
   from; es-latam/es-spain only have a `.pt` sibling, pt-br/pt-pt only have a `.es` sibling.
3. **Register the side tables** in `data/tracks/l10n/index.js`. This IS safe and inert:
   `getL10n(trackId, "fr")` is only reachable when `sourceLang === "fr"`, which cannot happen
   while `fr` is absent from `RELEASED_SOURCE_LANGS` and from the picker.
4. **Leave `data/tracks/index.js` and `lib/uiLang.js` untouched.** Both belong to the flip.
5. **Write the flip diff, don't apply it.** Produce `docs/_fr-offering-flip.md` containing the
   exact, complete patch that will make French reachable — the two imports, the two `TRACKS`
   entries, `RELEASED_SOURCE_LANGS` += `"fr"`, `SUPPORTED_UI_LANGS` += `"fr"` — plus the offering-flip
   checklist (`claude/squirrelingo_offering_flip_checklist.md`) run against it. That is the artifact I sign off on.

**Phase 3's parity audit therefore runs against a SIMULATED registry**, not the shipped one:
write a throwaway harness that imports the two new track files, merges them into a copy of
`TRACKS`, adds `fr` to a copy of `RELEASED_SOURCE_LANGS`, and asserts `tracksForNativeLang("fr")`
returns **12 tracks, all at full grammar depth, both variants where the target is split, no
stubs**. Keep the harness out of the repo, or put it under `scripts/` clearly marked as a
one-off. Do not weaken the assertion to make it pass.

- `npm ci`, never `npm install`. **Don't run the E2E suite** — it needs secrets and writes to the
